# 中断：当前边界与 Phase 2 设计

**当前没有自有 GDT、IDT、异常处理、PIC 或 PIT 驱动。**
内核依赖 Limine 的入口 CPU 环境，立即执行 `cli`，全程保持 IF=0。
GDB 验证此状态，正常停在 HLT 不代表定时器运行。

Phase 2 将按以下顺序实现与测试：

1. 安装内核 GDT（明确代码/数据段与后续 TSS 前提），加载 IDT。
2. 汇编异常入口保存寄存器；区分 CPU 自动压入错误码与无错误码向量，维持 C ABI 栈对齐。
3. 统一异常现场，输出向量、错误码、RIP；页故障额外读取 CR2。
4. 重映射并屏蔽 8259 PIC，确保异常与硬件 IRQ 不冲突；建立正确 EOI 流程。
5. 配置 PIT channel 0，建立真实 tick 计数；完成后才允许 `sti`。
6. 使用独立测试镜像/受控恢复点触发 `int3`、除零和页故障，并观察真实 IRQ 与计数增长。

硬件前提是 QEMU PC 兼容传统 8259/PIT/PS2，不能默认适用于无传统设备的任意实机。
预期异常的恢复必须明确测试入口及返回点，不能简单跳过任意故障指令。
当前误触发异常可能 triple fault；自动测试没有把它包装成“异常处理已通过”。
