# 内存管理：当前边界与 Phase 3 设计

**当前无物理分配器、无虚拟页映射 API、无堆。**
当前 Phase 1/2 使用 ELF 静态存储、64 KiB 启动栈和 Limine 提供的 framebuffer 虚拟地址；
Phase 2 新增的 GDT/IDT/TSS 与 DF IST 栈也都是静态存储，并非动态页分配。
CR3 读取值用于观察启动页表，不能称为已实现虚拟内存管理。

Limine 完成长模式和启动映射；不能假定所有物理地址可直接解引用，也不能假定固定 HHDM 偏移。
后续必须请求并解析 memmap/HHDM，区分可用、保留、内核、模块、framebuffer、引导器可回收内存。
建立自己的页表与栈前不得回收其仍依赖的引导器内存。

Phase 3 计划以 4 KiB 页为基础：

1. 从可用区建立页帧位图，向内对齐可用区、向外对齐保留区，检测整数溢出和内存孔洞。
2. 提供页帧分配/释放；检测双重释放、未分配页释放、错误对齐和耗尽。
3. 实现 x86-64 四级页表遍历，明确物理地址与内核虚拟地址转换。
4. 映射/解除映射后执行必要的 `invlpg`；明确可写、可执行、用户/内核权限。
5. 在 IDT 页故障处理可用后测试真实映射写读、别名、解除映射故障与错误码。

上述检查均未在当前阶段执行。现有 runtime 测试只覆盖字节内存操作，不证明页分配或 MMU API 正确。
